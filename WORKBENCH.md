## Локальная среда

ES, NQ, YM; каждый целый ТФ 1–1440; лента 2006-01-05 … 2026-05-04.
Поле построено, заморожено и открыто только на чтение.

```powershell
python -B -m g3riz.cli status
python -B -m pytest tests -q -p no:cacheprovider
```

Статус должен видеть 4 320 ячеек. Живая перепись главнее снимка
`PROJECT_STATE.json`. Свежий клон больших локальных массивов не содержит:
без подключённых `data/market` и `data/field` статус их не увидит. Это
ограничение доступа, а не потеря данных, и пересборку оно не разрешает.

Подключение — существующие каталоги `data/market/<инструмент>/` и
`data/field/<инструмент>/` внутри корня клона: обычные папки либо ссылки на
имеющуюся локальную копию. Проверяй `corpus_id` по `SOURCE_DATA.json` и
манифестам; число ячеек само по себе не удостоверяет происхождение байтов.
Если нужных массивов на машине нет, документацию и код можно изучать сразу;
для расчёта требуется местоположение готовой копии с установленным происхождением.

Среда общего слоя — `pip install -e ".[dev]"`, то есть numpy/pandas/pyarrow и
pytest из `pyproject.toml`; ничего сверх этого он не требует. Зависимости
конкретного расчёта живут рядом с ним: `setups/S-05/requirements.txt` добавляет
`numba`, `matplotlib` и `exchange_calendars`, нужные S-04…S-07, а не проекту.

[`.github/workflows/tests.yml`](.github/workflows/tests.yml) гоняет только этот
общий слой. Поле в CI не загружается и не материализуется; всё помеченное
`needs_field` там пропускается, и пропуск означает «не смотрели», а не «пусто».
Предметные проверки кандидатов CI не запускает и покрытием исследований не
притворяется: `python -B -m pytest setups/S-07/test_execution.py`.

Менять идентичности, пересобирать поле или возвращать materializer можно только
по отдельному решению трейдера: новое поколение семантики либо восстановление
после подтверждённой потери. Materializer лежит в истории git.

## Чем читать

Быстрое чтение нескольких паспортов, без изменения поля:

```powershell
python -B -m g3riz.cli query --instrument NQ --tf 54 --limit 3
```

Это адреса для чтения сцены: полный паспорт содержит поздние сведения и
не является готовым префиксом решения.

`Field.passports`, `events`, `film`, `films`, `minute_windows`, `objects_at`.
Рабочий пример и сборка сцены — в [`reference/`](reference/README.md).

`Film` имеет один T0, отрицательный pre-roll и явно названный конец: удаление,
конец Blue, край архива, бюджет наблюдения или `end_position` исследования.
`film.truncate(p)` показывает то, что было доступно к минуте `p`.

`core_tracks` — механические чтения. Выбор порога, окна или задержки — уже
именованная исследовательская линза; переиспользуемые живут в
`src/g3riz/lenses/`. Изменение смысла линзы получает новую версию, а не тихую
правку старой. Треки и линзы считают; статус знанию присваивает исследователь.

параметры, команда и происхождение входов сохраняются вместе с карточкой.
Общий слой чтения не задаёт длительность, отбор или правила сделки: это код
конкретного кандидата. Не добавляй универсальный движок без реальной потребности.

## Проверка входа

```powershell
python -B -m g3riz.cli entry-check make --version 2 --paper work/NNN/paper.md --key <вне репозитория>
python -B -m g3riz.cli entry-check score --key <ключ> --answers work/NNN/answers.json
```

Пять пар анонимизированных сцен и задача о раннем состоянии до будущего
паттерна. Сверяются ответы и выбранные исследовательские решения; коротких
полей недостаточно. Версия 1 оставлена для старых прогонов. Что измерено — в
[`reference/ENTRY_CHECK.md`](reference/ENTRY_CHECK.md).
