# Повторение S-07

[Карточка](../S-07-drayf-pervyh-minut-sessii.md): дрейф первых минут сессии,
сторона по предрыночному положению цены. Поле RIZ не требуется — нужны только
минутные массивы `data/market/<ins>/` и календарь из S-04.

Из корня `g3-market-research`. Общий слой чтения поля (`pip install -e .`,
`python -B -m pytest tests`) обходится numpy/pandas/pyarrow из
[`pyproject.toml`](../../pyproject.toml) — этому расчёту нужно больше. Среда как
у S-05: Python 3.14.4, [зависимости](../S-05/requirements.txt): сверх общего слоя
здесь нужны `numba` (`run.py`), `matplotlib` (`scenes.py`) и
`exchange_calendars` (для пересборки календаря S-04, готовый `calendar.parquet`
её не требует). Локально — `data/tmp/s04-venv`.

## Повторить текущий результат

Зависимости установи один раз в выбранной среде Python, из корня репозитория:

```powershell
python -m pip install -e ".[dev]" -r setups/S-05/requirements.txt
```

Для проверки полного правила v1 в ревизии v1r1 достаточно:

```powershell
python -B setups/S-07/revision.py --check
python -B -m pytest setups/S-07/test_execution.py -q -p no:cacheprovider
```

Повтор записывается в `data/research/S-07/recheck/` и сравнивается с
`result_v1r1.json`. Заморозка и сохранённый итог остаются источниками сверки.

## Как был получен результат

Ниже — команды разных этапов исследования, а не очередь для обычного повтора.
Они включают перебор и запись результатов рядом с карточкой; выбирай конкретный
скрипт по вопросу. Текущий повтор выше не требует заново проходить эти этапы.
`freeze.py` создавал `FROZEN_v1.json` и при повторном запуске перезапишет его.
Это исторический генератор: существующая заморозка сохраняется без перезаписи.

```powershell
python -B setups/S-07/run.py
python -B setups/S-07/verify.py
python -B setups/S-07/field.py across
python -B setups/S-07/manage.py
python -B setups/S-07/scenes.py
python -B setups/S-07/portfolio.py
python -B setups/S-07/stopstudy.py
python -B setups/S-07/stencil.py
python -B setups/S-07/stencil2.py
python -B setups/S-07/reconcile_swings.py
python -B setups/S-07/revision.py
python -B setups/S-07/revision.py --check
python -B -m pytest setups/S-07/test_execution.py -q
```

`test_execution.py` не попадает в `python -B -m pytest tests`: `testpaths` в
`pyproject.toml` собирает только `tests/`, и это намеренно. Общий слой страхует
чтение поля, а не исследования; предметные проверки кандидата запускаются
отдельной командой выше и без локальных `data/market` честно пропускаются.

`run.py` считает все 675 конфигураций (3 инструмента × минуты решения 0–14 ×
горизонты 30/60/120 × стопы 0/2/4/6/10 свечей) и пишет `summary_v1.csv` и
`data/research/S-07/trades_v1.parquet` со всеми сделками. `verify.py` даёт
устойчивость, стоимость годового выбора среди всех конфигураций и физическое
обрезание ленты. `field.py` — отвергнутая проверка живого RIZ как фильтра;
для неё нужны копии паспортов `data/research/S-06/<ins>_objects.parquet`
(готовятся `python -B setups/S-06/run.py prepare`).

| Перенос правила на TradingView | `S07_opening_drift.pine` |
| Хеши кода | `run_hashes_v1.json`, `FROZEN_v1.json` |
| Совместимость с прежними линиями | `portfolio_v1.json`, `portfolio_daily_v1.csv` |

Числа самой версии v1 живут в `result_v1r1.json` и вычисляются `revision.py`.
Раньше их не было ни в одном файле: `manage.py` печатал их в stdout, а
`freeze.py` вписывал две денежные суммы (`nq_m3_h120_managed_2020_total` и
`nq_m3_h120_nostop_2020_total`) в `FROZEN_v1.json` **константами**. Константы
верны — это теперь проверено счётом, — но заморозка остаётся историческим
свидетельством, а не источником чисел. `FROZEN_v1.json` не переписывается:
`revision.py --check` кладёт повтор в `data/research/S-07/recheck/` и сверяется
с сохранённым итогом. Хеш `.pine` в заморозке относится к переносу до ревизии
(коммит `ced8fa6`).

В `management_v3.csv` лежит то же ведение без предела: $240 505, просадка
$32 460, медиана −$275, остаток без лучших 5% −$159 030.

Скрипты разбора отвечают на отдельные вопросы о версии v1.
`portfolio.py` берёт сохранённые дневные ряды и отвечает, стоит ли держать S-07
вместе с прежней совместной линией S-04/S-05/S-06. `stopstudy.py` считает
профиль просадки внутри сделки и сетку «уровень стопа × момент выхода из минуса»
по эпохам. `stencil.py` раскладывает каждый день на подтверждённые свинги, ноги
и перелои и проверяет стоп за свингом. `stencil2.py` проверяет, несёт ли эта
структура информацию иначе, и готовит данные трафарета. `reconcile_swings.py` сверяет собственный детектор свингов с линзой поля
`src/g3riz/lenses/swing.py`, как того требует AGENTS.md. Ни один из них не
переопределяет замороженные числа v1; их выводы живут в карточке.

`revision.py` — единственное место, где полное правило v1 (предел 16 свечей +
выход на 15-й минуте при минусе + 120 минут) исполнено одним куском. Он считает
две модели рядом: как считал код v1 и как считает ревизия v1r1 (при открытии
минуты за пределом заполнение идёт по этому open). Разница за 21 год — ноль
сделок и ноль долларов; это измерено, а не предположено. Что он не улучшает:
выход на 15-й и на 120-й минуте по-прежнему исполняется по close той же минуты.

Календарь — XNYS 4.13.2, America/New_York, исторические сокращённые сессии.
Единица «свеча» — медиана истинного диапазона последних 30 закрытых минут.
День без полного префикса или без минуты входа исключается, а не считается нулём.
Живого исполнения здесь нет; расход фиксированный, проскальзывание не моделируется.

Замороженная версия v1: NQ, решение на 3-й минуте сессии, вход по open 4-й,
лимит 16 свечей, выход на 15-й минуте при минусе, иначе 120 минут, без
безубытка и трейлинга. Менять параметры внутри v1 нельзя — новая проверка
получает новый номер версии и свою строку в истории выбора карточки.
