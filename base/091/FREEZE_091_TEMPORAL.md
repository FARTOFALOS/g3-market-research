# FREEZE 091-TEMPORAL — замороженное торговое действие 086 для будущего NQ temporal test

Записано до появления новой NQ-ленты. Лента NQ заканчивается 2026-05-04 — ровно на
границе слабого holdout 086. Нетронутого NQ-периода нет, поэтому primary temporal
test сейчас не запускается. Здесь замораживается **полное торговое действие**,
чтобы будущий тест мерил конкретного трейдера, а не сумму независимых сцен. После
заморозки — без оптимизации concurrency, sizing, selection, re-entry, target, stop,
timing и фильтров. `Volume` не используется.

## 0. Наследуется из 086/091 без изменений

- Событие — замороженный `close_break → q_event`, популяция 084.
- Клетка `u+ k- ttc- r-`, исходные cutpoints (`base/086/cells086.json`) и знак −1
  (сторона продолжения), `base/086/selected086.json` (трекаемые копии frozen-выходов;
  локальный источник — `work/086/`).
- Continuation side без изменений: target = `a` (первый тик за `M`), opposite = `b`.
- Вход `open(q_event+1)`, cost 1.00 пт round-trip. Геометрия/автомат — `fork086.py`.

## 1. Single-unit execution policy (ратифицирована)

- 1 контракт на взятый сигнал; **не более одной открытой позиции одновременно**.
- Пока флэт: eligible берётся с самым ранним `q_event`; точный тай → наименьший
  `riz_id` (детерминированно, вне исхода).
- Пока позиция открыта: все новые сигналы → `skipped_overlap`; без пирамиды и
  усреднения.
- Выход — первое касание `a`/`b` с бара `q_event+1`.
- **Re-entry (уточнено):** в ту же RIZ-сцену — запрещён. После выхода следующий
  сигнал eligible, только если его собственный `q_event` произошёл **не раньше бара
  выхода** и его `open(q_event+1)` ещё **в будущем** относительно момента, когда
  позиция стала flat. Сигналы, возникшие во время занятой позиции, ретроспективно не
  подбираются.
- Расходы — 1.00 пт на **фактически взятую** позицию; пропущенные — ноль,
  считаются отдельно.

## 2. Точность 1 — что именно утверждает результат

`single-unit` — это **execution policy, не свойство edge**. Она сознательно
отбрасывает часть сигналов в кластерах. Основной будущий результат относится к
утверждению «вот что получает трейдер, торгуя frozen 086 по одной позиции за раз»,
а **не** к математическому expectancy всех отдельных 086-сцен.

## 3. Точность 2 — единица зависимости и inference

Overlap-policy меняет единицу зависимости: решение пропустить следующую сцену
зависит от длительности предыдущей позиции. Поэтому:

- строится **реализованный последовательный дневной ряд net P&L** после
  sequential/overlap-фильтрации;
- блочный/дневной bootstrap (блоки 1/5/20 календарных дней, протокол 086) делается
  **на этом action-stream**, а не на взятых сделках как на независимых.

## 4. Точность 3 — unknown до результата

Для `same_bar / lost_observability / archive_edge` **не** выбирается благоприятная
конвенция после того, как виден будущий исход. Публикуется:

- identified economics (только разрешённые сделки);
- предобъявленные **favorable** и **adverse** bounds (все unknown → target / все
  unknown → stop).

Порог решения — **ноль net после расходов**. Само terminal decision rule —
единственное и задано в **§7.3 (CI-aware)**; §7.3 **supersedes** любое более грубое
чтение этого пункта. Здесь фиксируется только принцип: середину между favorable и
adverse bounds не угадывать.

## 5. Primary future outputs

- net expectancy на взятую позицию;
- дневной / кумулятивный реализованный net под замороженной sequential policy;
- target-first rate среди взятых;
- participation rate;
- skipped-overlap rate;
- unknown rate и экономические bounds (favorable/adverse/identified).

## 6. Условие активации

Запуск один раз, когда появится честно неиспользованный NQ-период после 2026-05-04.
Оператор применяется без изменений; знак/цель/стоп/клетка/cutpoints — как заморожено.
ES/YM — отдельный вопрос cross-instrument transport; NQ temporal persistence они не
решают и не «спасают».

## 7. Дополнения до data outcome (ратифицировано 2026-09-17, outcome-blind)

Оператор меняет **только источник данных**, не гипотезу. Ниже зафиксировано до
просмотра любого результата на новой ленте.

### 7.1 Fixed temporal territory (outcome-blind)
Primary temporal territory = все совместимые минуты NQ **строго после** последнего
timestamp существующей локальной ленты (2026-05-04) до последнего полного дня первого
**принятого** внешнего источника. Если первым прошедшим provenance/compatibility gate
источником окажется публичный GitHub sample с окончанием 2026-09-02, primary test
territory = фиксированный post-cutoff период **до 2026-09-02 включительно**. Окно не
сокращается и не расширяется после просмотра результатов.

### 7.2 Pre-entry gaps на `open(q_event+1)`
- open уже на/за целью `a` → `preentry_missed_target`, позиция **не** создаётся,
  P&L = 0;
- open уже на/за противоположной `b` → `preentry_invalidated_stop`, позиция **не**
  создаётся, P&L = 0;
- позиция создаётся только если executable open строго внутри живого интервала между
  frozen `a` и `b`.
Эти случаи публикуются отдельно. (Уточняет 091: pre-entry gap = нет сделки, P&L 0,
не −cost.)

### 7.3 Economic decision with uncertainty (единственное terminal decision rule)
Это **единственное** правило исхода temporal-теста; §4 к нему только отсылает. Порог primary
claim = **0 net пунктов** после frozen 1.00 pt round-trip. На frozen sequential
дневном action-stream, bootstrap 1/5/20 календарных дней:
- adverse-case (все unknown → stop) **нижняя** доверит. граница > 0 → **positive
  temporal result**;
- favorable-case (все unknown → target) **верхняя** граница < 0 → frozen 091 action
  **экономически проваливается** на этой территории;
- иначе → **UNRESOLVED**.
Новый практический ε после просмотра данных не вводится.

### 7.4 Source acquisition / compatibility (кратко; полный протокол — в задаче)
Внешний источник принимается для temporal test только если overlap с существующей
локальной лентой (предпочт. 2026-04-01 … 2026-05-04) воспроизводит ту же NQ
representation достаточно для бит-/семантически совместимого запуска 084→086→091:
совпадение timezone/минут/сессий/OHLC/тика/roll и **точное** согласие `q_event`,
`a`, `b`, cell membership и 091-исходов на overlap. Разрешены только механические
преобразования формата (tz, rename, parse, документированная детерминированная
ценовая правка, доказанная overlap'ом), без настройки под post-cutoff. Post-cutoff
запечатан до acceptance: до gate не считаются сигналы/target-first/stop/P&L после
2026-05-04. Не NQ (cash index, QQQ, CFD, MNQ иной семантики, 5m, RTH-only,
synthetic) не подменяет. Платный источник — только отдельным решением оператора.
