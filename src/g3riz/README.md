# `g3riz` — чтение замороженного поля

Этот пакет **считает и не делает выводов**. Он даёт доступ к прибитым фактам
поля и к именованным чтениям над ними; статус знания присваивает исследователь
в карточке, а не код. Правила работы — [`AGENTS.md`](../../AGENTS.md), состояние
поля и рабочие команды — [`WORKBENCH.md`](../../WORKBENCH.md).

Сборщик поля (materializer) из рабочего дерева убран и лежит в истории git —
коммит `dd278b6`, ветка `snapshot/pre-restructure`. Здесь его нет намеренно.

## Слои

| Модуль | Что делает |
|---|---|
| `market.py` | Доступ к замороженным минутным лентам ES/NQ/YM. Только чтение |
| `store.py` | Машинная перепись поля: сколько ячеек, какие готовы, что устарело |
| `schema.py` | Арроу-схемы паспорта, событий и ячейки плюс версии семантики. Меняются только с новым поколением поля |
| `identity.py` | Как считается `riz_id` и отпечаток кода сборщика. Идентичность объекта живёт здесь |
| `query.py` | Основная рабочая поверхность: `Field.passports`, `events`, `film`, `films`, `minute_windows`, `objects_at` |
| `film.py` | `Film` — минутная жизнь одного RIZ вокруг его T0. Не хранится в поле, строится по запросу; `film.truncate(p)` даёт префикс, доступный к минуте `p` |
| `tracks.py` | Тринадцать механических чтений одной минуты. Порогов не выбирают |
| `lenses/` | Чтения фильма, которые исследование обязано запросить по имени |
| `cli.py` | Командная строка: `status`, `query`, `entry-check` |
| `entry_check.py` | Экзамен для самого входа: анонимизированные сцены и ключ. К исследованию рынка отношения не имеет |

## Где проходит граница между треком и линзой

**Трек** — чтение, у которого нет свободного числа: `H`, `RUN_MAX` и остальные
одиннадцать читаются одинаково у всех. **Линза** — чтение, которому нужен выбор:
ширина фрактала, амплитуда отката, порог взаимодействия. Такой выбор уже
исследовательское решение, поэтому линза запрашивается по имени и версии, а
изменение смысла линзы даёт новую версию, а не тихую правку старой.

| Линза | Что читает |
|---|---|
| `lenses/swing.py` | Строгие трёхбаровые пивоты `strict3_v1` и, отдельно, минута, на которой каждый становится **узнаваемым** (`confirmed_at`). Смотреть вперёд можно только от второй |
| `lenses/legs.py` | Фильм, разрезанный на чередующиеся ходы по названной амплитуде отката `theta` |
| `lenses/interaction.py` | Способы спросить минуту, взаимодействовала ли она с RIZ или с его выходной границей |

Прежде чем писать собственный детектор свингов или ног, прочитай докстроки этих
двух файлов: там записано, что на поле 2006–2026 медианный фильм несёт около 25
строгих трёхбаровых пивотов и 49 смен знака close-to-close за 120 минут, что
это свойство минутного шума, и что развёртка `theta` от 0,10 до 3,00 ATR даёт
плавное падение числа ног с 41 до 5,4 без всякого плато. Там же перечислены три
уже провалившихся аргумента против линзы ног. Свой оператор, меряющий то же
самое, полагается сверить с этими линзами на конкретных фильмах.

## Чего здесь нет и не будет

Общий слой не задаёт длительность сделки, отбор дней и правила исполнения: это
код конкретного кандидата и живёт рядом с его карточкой в `setups/S-NN/`.
Универсальный движок бэктеста сюда не добавляется без реальной потребности.
`tests/` страхует именно этот общий слой, а не исследования.
